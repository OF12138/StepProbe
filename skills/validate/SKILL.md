# /validate —— 评估器有效性验证

## 用途

**在用评估器去评测 Hy3 之前，先证明这个评估器本身是可靠的。**

做法：在 ProcessBench 等带专家人工标注的数据上跑评估器，把它的判断与人工标注对比。
指标是对着**第三方标注**算出来的，不是对着自己的标注 —— 这是本项目验证结论可信的关键。

## 可用的 MCP 工具（stepprobe）

| 工具 | 作用 |
|---|---|
| `dataset_next_batch(n, tier, label_class, run_id)` | 取一批样本（**已剥离标注**） |
| `metrics_compute(run_id)` | 算定位准确率 / 误报率 / 一致性 / 稳定性 |
| `report_export(run_id, kind)` | 导出结果表格或人工抽检清单 |

---

## 流程

### 1. 取样本

```
dataset_next_batch(n=40)                       # 首次调用，返回 run_id
dataset_next_batch(n=40, run_id="<上一步的 run_id>")   # 续取，自动不重复
```

按类别定向取样：`label_class` 可选 `faulty_wrong` / `clean_correct` / `e9`；
`tier` 可选 `T1`–`T4`。

抽样集共 447 条（4 个难度层 × 3 个标注类别）。受吞吐限制建议**分批跑**，
每批 20–40 条，用同一个 `run_id` 累积。

### 2. 逐条评估

对每条样本执行 `/evaluate` 的完整流程，结果用 `verdict_record` 落盘。

> **关键：此时看不到也不能去找标注。** `dataset_next_batch` 返回的数据已剥离 `label`
> 字段。若你以任何方式获知了 ground truth（比如去读 `data/sample_set.jsonl`），
> 本次验证作废 —— 请换一个新的 `run_id` 重来。

### 3. 稳定性验证

从已评估的样本里挑 30 条，各重复评估 5 次（同一 `run_id` 重复 `verdict_record`
即可，工具会保留全部记录）。

### 4. 计算指标

```
metrics_compute(run_id="latest")
```

产出：

**定位准确率**（在标注为「过程有误」的样本上）

| 指标 | 定义 |
|---|---|
| `detection_rate` | 判定「过程存在问题」的占比 |
| `exact_localization_acc` | 预测步号 == 标注步号 |
| `tolerant_localization_acc_pm1` | 允许 ±1 步偏差 |

分母统一为**全部有误样本**，未检出记为定位失败 —— 不在「检出的样本」里算准确率。

**误报率** `false_positive_rate` —— 在标注为「过程无误」的样本上。

**E9 召回** `e9_recall` —— 在「答案对但过程错」的样本上的检出率。

**错误类型一致性**、**分层结果** `by_tier`、**稳定性** `stability`。

所有比例指标附 Wilson 95% 置信区间（`ci95` 字段）。

### 5. 人工抽检（不可跳过）

```
report_export(run_id="latest", kind="human_audit")
```

生成 `results/runs/<run_id>/audit_sheet.csv`，每行含：原标注、评估器判断、证据、
步骤原文，以及待填的 `human_verdict` 列。

人工逐条填写 **真实问题**（原标注漏标，评估器其实是对的）或 **真误报**。

报告需同时给出**原始误报率**与**人工修正后误报率**。

> 这是任务书明确要求的产出（人工抽检记录），不能用自动方法替代。
> 可以先做一轮预审给出建议判断，但报告中必须注明哪些是人工确认、
> 哪些被人工推翻 —— **不把预审伪装成人工抽检**。

### 6. 导出

```
report_export(run_id="latest", kind="summary")
```

## 通过标准

验证结果需达到以下水平，评估器才可用于正式评测：

| 指标 | 门槛 | 理由 |
|---|---|---|
| `detection_rate` | 显著高于随机基线 | 否则评估器没有区分力 |
| `tolerant_localization_acc_pm1` | ≥ 0.5 | 至少一半样本能定位到出错位置附近 |
| `false_positive_rate`（人工修正后） | ≤ 0.2 | 误报会直接摧毁工具实用价值 |
| `stability.step_mode_ratio` | ≥ 0.6 | 否则结论只是随机波动 |

**未达标时不要调参数硬凑指标。** 如实记录未达标项，分析原因（提示词问题、切分粒度
问题，还是任务本身太难），写入 `docs/report.md`。

**一份诚实的失败分析比一个凑出来的漂亮数字更有价值** —— 后者在评审时经不起追问。

## 已有的 L1 基线

纯确定性层（不含任何模型判断）在同一批 447 条样本上的实测：

| 指标 | 数值 |
|---|---|
| 触发率 | 6.3%（28/447） |
| 触发时精确命中 | 39.3% |
| 触发时误报率 | 3.6%（1/28） |

L2/L3 的价值就在于把触发率从 6.3% 提上去，**同时不让误报率跟着涨**。
这条基线是评价整套评估器的参照系。
