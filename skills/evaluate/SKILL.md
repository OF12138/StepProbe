# /evaluate —— 过程评估

## 用途

对一条推理链给出结论：**是否成立 → 首错在第几步 → 属于什么错误类型**。

## 参数

| 参数 | 说明 | 默认 |
|---|---|---|
| `--run` | 要评估的解题批次，`latest` 表示最近一次 | `latest` |
| `--input` | 直接指定输入文件（可选） | — |

## 执行顺序（严格遵守）

### 第 1 步：确定性校验（MCP，不要自己算）

对每条链依次调用：

- `check.answer(final_answer, gold_answer, answer_format)` → 最终答案是否正确
- `check.step_symbolic(step)` → 逐步返回 `FALSE` / `UNKNOWN` / `TRUE`

**凡是能由工具判定的，一律以工具结论为准，不要用自己的计算覆盖它。** 这是本评估器可靠性的基础 —— 算术判定交给 SymPy，你负责语义判断。

若某步返回 `FALSE` → 判定 **E3 计算错误**，记录该步号，**跳到第 3 步**（仍需 L3）。

### 第 2 步：分步审查（你来判断）

**只审查第 1 步中返回 `UNKNOWN` 的步骤。**

对每一步，在「前面所有步骤都成立」的前提下，判断当前步是否成立。负责三类：

- **E2 概念/定理误用** —— 必须指出定理名称与不满足的前提
- **E5 跳步推导** —— 必须写出缺失的中间环节是什么
- **E7 幻觉引用** —— 必须指出被引用对象既不在题干中，也非公认数学事实

#### 三条硬性约束

1. **不要参考最终答案是否正确。** 即使你能看出答案错了，也不要因此提高挑错倾向；即使答案对了，也不要因此放松审查。结果偏置会同时污染定位准确率与误报率两个核心指标。

2. **默认成立，举证判错。** 只有在能指出具体问题时才判错，不确定时判"成立"。**宁可漏报，不可误报。**

3. **逐步独立判断。** 不要因为看到后面的步骤而反推前面步骤的对错 —— 我们要定位的是**首个**错误。

### 第 3 步：全局复核（必须执行）

**无论前面是否已经找到错误，这一步都要跑。**

判定四类链级问题：

| 类型 | 复核方式 |
|---|---|
| **E1 题意误读** | 比对解答实际求解的目标与题干所问 |
| **E4 条件遗漏** | 列出题干全部条件，逐一检查是否被使用；对未使用的条件追问"去掉它结论是否改变" |
| **E6 循环论证** | 检查是否有某步的依据实质上是待证结论 |
| **E9 答案对但过程不成立** | **仅当 `check.answer()` 返回正确时触发**，见下 |

#### E9 的三重信号（至少两项命中才判定）

1. **依据充分性** —— 最终答案是否由前序步骤逻辑推出，还是凭空出现？
2. **扰动检验** —— 若题目条件轻微改变，这条链会给出什么答案？链条正确则答案应随之改变；实为猜测则往往不变或明显荒谬。
3. **步骤删除检验** —— 删去某关键步骤后结论是否仍"成立"？若是，说明该步骤本就未被真正使用。

E9 的误判代价很高（把正确解答判为"蒙对"会严重损害可信度），因此证据阈值高于其他类型。

### 第 4 步：落盘

调用 `verdict.record(sample_id, verdict)`。

## 输出规范

**严格 JSON，不含其他文字：**

```json
{
  "sample_id": "processbench-math-0123",
  "answer_correct": true,
  "process_valid": false,
  "first_error_step": 4,
  "error_type": "E9",
  "evidence": "第 4 步由 f 连续直接得出 f 有最大值，未说明定义域为闭区间；最终答案正确系因所给区间恰为闭区间，属巧合。",
  "layer": "L3",
  "e9_signals": ["grounding", "step_deletion"]
}
```

- `process_valid` 为 `true` 时，`first_error_step` 与 `error_type` 填 `null`
- `evidence` **不得为空**，且必须指向具体论断，不接受"推理不够严谨"这类表述
- `layer` 记录由哪一层做出判定，用于后续分析各层贡献
