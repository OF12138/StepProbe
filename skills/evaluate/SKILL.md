# /evaluate —— 过程评估

## 用途

对一条推理链给出结论：**是否成立 → 首错在第几步 → 属于什么错误类型**。

## 可用的 MCP 工具（stepprobe）

| 工具 | 作用 |
|---|---|
| `check_step_symbolic(steps)` | 逐步确定性校验，返回 FALSE / UNKNOWN / TRUE |
| `check_answer(pred, gold)` | 最终答案三级校验 |
| `check_format(answer, requirements)` | 形式要求校验（仅题目明确要求时用） |
| `verdict_record(run_id, verdict)` | 落盘一条评判结果 |

---

## 执行顺序（严格遵守）

### 第 1 步：确定性校验（调工具，不要自己算）

```
check_step_symbolic(steps=[...])
```

返回里有两个关键字段：

- `first_false_step` —— 确定算错的步号（1-based）。非空即判 **E3 计算错误**
- `needs_llm_review` —— 需要你做语义审查的步号列表

**只审查 `needs_llm_review` 里的步骤。** 工具已判定的步骤不要用自己的计算去覆盖 ——
算术判定交给 SymPy，你负责语义判断。这是本评估器可靠性的基础。

若题目有标准答案，另外调 `check_answer(pred, gold)`。

> 工具返回 `TRUE` **不代表整条链成立**。每步算对不等于论证成立 —— E9 正是这么产生的，
> 所以第 3 步必须执行。

### 第 2 步：分步审查（你来判断）

对 `needs_llm_review` 中的每一步，在「前面所有步骤都成立」的前提下判断当前步是否成立。
负责三类：

- **E2 概念/定理误用** —— 必须指出定理名称与不满足的前提
- **E5 跳步推导** —— 必须写出缺失的中间环节是什么
- **E7 幻觉引用** —— 必须指出被引用对象既不在题干中，也非公认数学事实

#### 三条硬性约束

1. **不要参考最终答案是否正确。** 即使看出答案错了也不要因此提高挑错倾向；即使答案
   对了也不要因此放松审查。结果偏置会同时污染定位准确率与误报率两个核心指标。

2. **默认成立，举证判错。** 只有能指出具体问题时才判错，不确定时判「成立」。
   **宁可漏报，不可误报。**

3. **逐步独立判断。** 不要因为看到后面的步骤而反推前面步骤的对错 —— 要定位的是
   **首个**错误。

### 第 3 步：全局复核（必须执行）

**无论前面是否已找到错误，这一步都要跑。**

| 类型 | 复核方式 |
|---|---|
| **E1 题意误读** | 比对解答实际求解的目标与题干所问 |
| **E4 条件遗漏** | 列出题干全部条件，逐一检查是否被使用；对未使用的条件追问「去掉它结论是否改变」 |
| **E6 循环论证** | 检查是否有某步的依据实质上是待证结论 |
| **E9 答案对但过程不成立** | **仅当 `check_answer` 返回 correct=true 时触发**，见下 |

#### E9 的三重信号（至少两项命中才判定）

1. **依据充分性** —— 最终答案是否由前序步骤逻辑推出，还是凭空出现？
2. **扰动检验** —— 若题目条件轻微改变，这条链会给出什么答案？链条正确则答案应随之
   改变；实为猜测则往往不变或明显荒谬。
3. **步骤删除检验** —— 删去某关键步骤后结论是否仍「成立」？若是，说明该步骤本就
   未被真正使用。

E9 误判代价很高（把正确解答判为「蒙对」会严重损害可信度），证据阈值高于其他类型。

### 第 4 步：落盘

```
verdict_record(run_id="<本批次的 run_id>", verdict={...})
```

---

## 输出规范

`verdict` 必须是如下结构。**判错时 `evidence` 为空会被工具直接拒绝。**

```json
{
  "sample_id": "processbench-math-math-123",
  "answer_correct": true,
  "process_valid": false,
  "first_error_step": 4,
  "error_type": "E9",
  "evidence": "第 4 步由 f 连续直接得出 f 有最大值，未说明定义域为闭区间；最终答案正确系因所给区间恰为闭区间，属巧合。",
  "layer": "L3",
  "e9_signals": ["grounding", "step_deletion"]
}
```

- `process_valid` 为 `true` 时，`first_error_step` 与 `error_type` 填 `null`
- `evidence` **不得为空**，且必须指向具体论断 —— 不接受「推理不够严谨」这类表述
- `layer` 记录由哪一层做出判定（L1 / L2 / L3），用于分析各层贡献
- `first_error_step` 是 **1-based**

## 批量处理

受吞吐限制，一次处理一批样本时：**整条链一次评审完再落盘**，不要逐步骤各调一次模型。
`check_step_symbolic` 一次传入全部步骤，只对它标出的 `needs_llm_review` 做语义判断。
