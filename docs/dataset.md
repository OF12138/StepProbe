# 评测数据说明

本文说明评测样本的来源、构造方式、难度分层依据与抽样方案。

---

## 1. 设计原则

**过程标注优先复用公开人工标注，不做大规模自行标注。**

理由：本项目的核心是**验证评估器是否可靠**，而验证需要"首个错误步骤"的可信 ground truth。自行标注数百条推理链既昂贵又难以保证质量，而 ProcessBench / PRMBench / DeltaBench 已提供由专家标注的步骤级标签。复用它们，既省去标注成本，也让验证结论更有说服力 —— 指标是对着第三方标注算出来的，不是对着自己的标注算出来的。

**代价与应对**：完全依赖公开基准会让项目缺少自建成分。因此额外构建一个**中文子集**用于评测执行（§4），使项目既有可信的验证依据，也有自主构造的评测内容。

---

## 2. 数据来源

| 数据集 | 规模 | 提供的标注 | 在本项目中的用途 |
|---|---|---|---|
| **ProcessBench** | 3,400 条 | 人工专家标注的**最早出错步骤**（0-based，-1 表示无误）；含"全部步骤正确"样本。**不提供标准答案**，只给 `final_answer_correct` 布尔值 | **主验证集**：定位准确率 + 误报率 + E9 |
| **PRMBench** | 6,216 题 / 83,456 步骤标签 | 步骤级标签 + 九类错误维度 | **错误类型一致性验证** |
| **DeltaBench** | 1,236 条（math 562 / code 373 / PCB 154 / general 147） | 长 CoT 分段标注：首错段号 + 解释 + 修正。实测 math+code 子集 **`final_correct` 全为 0**，即全部为答案错误样本 | **仅用于定位能力的跨域泛化验证** —— 无法测误报率，也不含 E9 |
| **自建中文子集** | 目标 100–150 题 | 标准答案（可自动校验） | **评测执行**：Hy3 的实际表现 |

### 为什么 ProcessBench 是主验证集

它是唯一同时满足三个条件的数据集：

1. 标注的正是**最早出错步骤**（与任务书的"定位错误发生的步骤"完全对应）
2. 包含**"全部步骤正确"的样本**，可直接用于测量误报率 —— 这是任务书明确要求的指标，而多数数据集只有错误样本
3. 题源天然构成难度阶梯（见 §3）

---

## 3. 难度分层与分层依据

ProcessBench 由四个来源构成，其本身即为一条经过社区广泛验证的难度阶梯，直接作为分层依据：

| 层级 | 来源 | 总数 | 难度特征 | **E9 占比（实测）** |
|---|---|---|---|---|
| **T1 基础** | GSM8K | 400 | 小学应用题，四则运算与简单代数 | 1.75% |
| **T2 中等** | MATH | 1000 | 高中竞赛，代数 / 几何 / 数论 / 概率 | 9.40% |
| **T3 困难** | OlympiadBench | 1000 | 奥赛级别，需要构造与多步论证 | 16.10% |
| **T4 极难** | Omni-MATH | 1000 | 高难度竞赛题集 | 25.90% |

**分层依据得到了实证支持**：「答案对但过程错」的比例沿这条阶梯从 1.75% 单调升到 25.90%，说明该分层确实区分了推理难度，而不只是题目来源不同。

**分层依据的可靠性**：这四个来源的相对难度在公开评测中已被反复验证（各主流模型在其上的准确率呈单调下降）。相比自行按"感觉"分层，采用既有题源作为分层依据更客观、也更容易被复核。

**补充分层维度**：在报告中同时按**推理链长度**（步数）二次分层，用以区分"题目本身难"与"链条长导致出错概率累积"这两个不同因素。

## 4. 自建中文子集

### 构造方式

| 项 | 说明 |
|---|---|
| **题源** | 近年高考数学真题、高中数学联赛初赛题 |
| **规模** | 目标 100–150 题 |
| **筛选标准** | 答案必须**可自动校验** —— 数值、闭式表达式、区间或集合；排除证明题与作图题 |
| **分层** | 二维：题源（高考 / 联赛）× 参考解法步数（≤5 / 6–10 / >10） |
| **标注** | **仅标注标准答案**，不人工标注过程 —— 过程标签由已验证的评估器产出 |

### 为什么中文子集不做过程标注

评估器的可靠性已在 ProcessBench 上用第三方人工标注验证过（`docs/method.md` §7）。在此前提下，用它去评测 Hy3 在中文题上的表现是合理的 —— 这正是"先验证工具、再用工具测量"的标准流程。

对评估器与人工判断不一致的样本，仍会人工复核并记入 `results/human_audit/`。

### 版权与合规

高考真题与联赛题为公开发布的考试内容。仓库中**只存放题目 ID、来源标识与结构化答案**，不分发受版权保护的题目原文与官方解析；构建脚本从公开来源获取原文并在本地生成数据集。

## 5. 抽样方案

### 5.1 为什么抽样

WorkBuddy 无批量推理 API，全部模型调用发生在 Agent 轮次中（README §10）。ProcessBench 全量 3,400 条在此约束下不可行。

### 5.2 分层抽样设计

按 4 个难度层 × **3 个标注类别** 分层，每单元 40 条：

| 类别 | 含义 | 用途 | 实际抽取 |
|---|---|---|---|
| `faulty_wrong` | 过程有误 + 答案错误 | 定位准确率 | 160 |
| `clean_correct` | 过程无误 + 答案正确 | 误报率 | 160 |
| `e9` | **过程有误 + 答案正确** | E9 识别能力 | 127 |
| **合计** | | | **447** |

（T1/e9 全量仅 7 条，不足 40 故全取，因此 e9 类为 127 而非 160。）

**为什么是三类而非两类**：定位准确率只能在"有误"样本上算，误报率只能在"无误"样本上算，而 E9 是任务书点名要求识别的类型 —— 三者各自需要足量样本。若按原始比例抽样，E9 会被淹没在多数类里。

**为什么各类等量而非按真实比例**：保证三个核心指标的样本量相当，不出现"某个指标只有十几条样本支撑"的情况。

**代价**：该抽样不反映真实错误率分布，因此**不能**用它估计"模型总体过程正确率"。报告中所有基于抽样集的指标都会标注这一点；总体分布相关的结论只在自建中文子集（全量评测）上给出。

### 5.3 置信区间

每个单元 40 条，比例型指标的 95% 置信区间半宽约为 ±15 个百分点（最坏情况 p=0.5）；按类别汇总（约 160 条）时收窄到约 ±8 个百分点。这意味着：

- **可以**支撑"定位准确率显著高于随机基线"这类结论
- **可以**支撑跨难度层的大幅差异（相差 >20 个百分点）
- **不能**支撑"T2 比 T1 高 3 个百分点"这类精细比较

报告中所有比例指标均给出 Wilson 置信区间，并明确避免在区间重叠时宣称差异。

### 5.4 随机种子

抽样使用固定随机种子（`configs/default.yaml` 中的 `seed`），抽中的样本 ID 列表随结果一并提交，保证可复现。

## 5.5 P6 消融题目集：反推出来的标准答案

前面的抽样集用于**验证评估器**，标注是现成的。P6 要评的是 Hy3 自己解题的能力，
需要的东西不一样：**题目 + 标准答案**，而且解题时不能看到答案。

**问题是 ProcessBench 没有标准答案。** 四个 parquet 的列只有 id / generator /
problem / steps / final_answer_correct / label —— 447 条样本 `gold_answer` 全为空。

**做法**：被标为 `final_answer_correct=True` 的解答，其最终答案按数据集的断言就是
对的，抽出其中的 `\boxed{...}` 即可（`scripts/build_p6_set.py`）。

**可靠性是测出来的，不是假设的。** ProcessBench 里有 110 道题被两个以上不同模型
答对过，构成天然的交叉印证集 —— 两次独立抽取是否等价，直接给出抽取器的可靠性：

| | 实测 |
|---|---|
| `\boxed` 抽取率 | 90.1%（1532/1700） |
| 交叉印证一致率 | **95.5%**（105/110） |
| 产出题目集 | **160 道**，T1–T4 各 40 |
| 其中标准答案有交叉印证 | 11 道 |

**为什么接受单条抽取（`min-agree=1`）。** 若只保留有交叉印证的题目，T2 与 T4 一道
都剩不下 —— ProcessBench 各子集大多「一题一模型」，只有 olympiadbench 大量复用题目，
结果会是个只有 T3 的畸形集合。接受约 2% 的标准答案噪声，理由是 **P6 是同题配对
对比**：两个 arm 解同一批题，标准答案抽错时两臂被同等惩罚，误差在配对差分中抵消。
噪声因此只影响绝对准确率，不影响 P6 要回答的那个问题。

**已知偏置（报告中必须写明）**：能这样反推出答案的题目，都是**至少被一个模型答对
过的**，系统性偏易。绝对准确率不可与其他工作横向比较；配对差分不受影响。

**防泄漏**：MCP 工具 `p6_next_batch` 按 `store.P6_SAFE_KEYS` 白名单发题
（`id` / `problem` / `tier`），**标准答案不出服务端**，只在 `scripts/p6_score.py`
评分阶段参与比对。这与验证集剥离 `label` 是同一条纪律，且同样有专门的测试守着
（`tests/test_p6.py`）。

## 6. 统一数据 Schema

各数据集经 `stepprobe.data` 规整为统一结构：

```json
{
  "id": "processbench-math-math-123",
  "source": "ProcessBench",
  "tier": "T2",
  "problem": "题目文本",
  "gold_answer": null,
  "solution_steps": ["步骤1", "步骤2", "..."],
  "label": {
    "process_correct": false,
    "first_error_step": 4,
    "answer_correct": true,
    "error_type": null,
    "annotator": "human"
  },
  "meta": { "original_id": "...", "split": "math", "generator": "...", "raw_label": 3 }
}
```

**步号一律 1-based。** ProcessBench 原始 `label` 为 0-based（`-1` = 全部正确），在 loader 中转换，并对越界值直接报错而非静默通过。

`gold_answer` 为可选 —— ProcessBench 不提供，DeltaBench 与自建中文子集提供。

评估阶段通过 `Sample.without_label()` 取样本，**标注字段必须剥离**：一旦 ground truth 进入模型上下文，本次验证即作废。

| 数据集 | 使用方式 |
|---|---|
| ProcessBench | 遵循原始许可，仅在本地使用，不二次分发原始数据 |
| PRMBench | 同上 |
| DeltaBench | 同上 |
| 自建中文子集 | 仓库仅存题目 ID 与结构化答案，不分发题目原文 |

### 5.6　P6 题目集的实测缺陷（执行后补记）

P6 跑完 320 条后逐条审计，题目集本身暴露出两类问题，记录在此供后续复用者参考：

**一、约 2.5% 的题目在脱离原数据集上下文后不可解。** 命中 4 道：

| 题号 | 问题 |
|---|---|
| `p6-t3-024` | 接力题，题面引用「position 7 / position 9 的结果」，这两个值不在本题里 |
| `p6-t4-026` | 题面引用「the given drawings」，图形不在文本中 |
| `p6-t4-035` | 使用了未定义的术语（consistent k-configuration） |
| `p6-t4-033` | 答案是一个几何作图描述，`\boxed{}` 抽出来只剩 `P, Q, R`，退化为无意义 gold |

这类题两臂都答不出，在配对差分中抵消，但会拉低绝对准确率。若重建题目集，
应加一道过滤：题面含 `position \d`、`the given (figure|drawing|diagram)`
等引用外部内容的模式时剔除。

**二、标准答案噪声已被具体证实。** `p6-t4-013` 的 gold 是 $3^{1991}$，
但 $\varphi(3^{1991}) = 2 \cdot 3^{1990}$ 不整除 $3^{1991}$，不满足题设；
模型给出的 $2^{1991}$ 才是对的。这落在 §5.5 承认的约 2% 噪声范围内，
但在只有 3 条配对不一致的情况下，单条错误 gold 就足以影响净值符号 ——
**配对设计降低了 gold 噪声的影响，没有消除它。**

**三、难度标签不等于实际难度。** T4（Omni-MATH）里存在这样的题：

> Find the area of the region between a circle of radius 100 and a circle of radius 99.

两步解完。tier 标签继承自源数据集的**题源**而非难度，加上「至少被一个模型
答对过」这道偏易筛选，导致 P6 题目集整体过易，过程成立率两臂都是 1.000，
消融的主角指标零方差（见 `docs/report.md` §6.3）。
