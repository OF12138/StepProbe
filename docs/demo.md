# Demo 口播稿与录制脚本（2 分钟）

这份稿子可以**一字不改从头念到尾**。每一幕分三块：

- **【画面】** 录屏里要出现什么
- **【操作】** 你要做的动作，按顺序执行
- **【口播】** 逐字念的内容，右上角标了字数

全片口播 **519 字**，按每分钟 270 字的讲解语速约 1:55；
加上约 14 秒的操作静默，成片 **2:09**。语速快一点就能压到两分钟以内。
念的时候不用赶 —— 宁可在【操作】处停一拍，也不要抢在画面前面。

---

## 一、录制前准备（提前 10 分钟做完）

**环境**

1. WorkBuddy 打开，把本仓库选为 workspace，确认 MCP 状态灯是 🟢
2. **关闭 Max Mode**（保持默认状态，避免观众问「你开了什么」）
3. 终端 `cd` 到仓库根目录，字号调到 16pt 以上，确保 1080p 下能看清
4. 关闭所有通知：微信、邮件、系统更新提醒
5. 浏览器只留需要的标签页，隐藏书签栏

**预热（很重要）**

6. 提前跑一次 `python scripts/build_p6_set.py`，避免录制时等待依赖加载
7. 提前用同一条样本试跑一次 `/evaluate`，确认 MCP 工具能正常调用
8. 预先打开这四个文件，排好切换顺序：

   | 顺序 | 文件 | 定位到 |
   |---|---|---|
   | 1 | `docs/report.md` | §1 的 E9 占比表 |
   | 2 | `README.md` | §3 四层架构 |
   | 3 | WorkBuddy 对话框 | 空白新会话 |
   | 4 | `results/runs/run-20260903T141258Z/audit_summary.md` | 顶部 |
   | 5 | `docs/report.md` | §6.2 的 P6 结果表 |

**待粘贴的素材**（提前放进剪贴板管理器或一个临时文本文件）

用于第三幕的推理链，原样复制：

```
/evaluate

题目：A number p is perfect if the sum of its divisors, except p, is p.
f(n)=0 if n is perfect; f(n)=0 if the last digit of n is 4; f(a·b)=f(a)+f(b).
Find f(1998).

步骤 1：先判断 1998 是否为完全数。1998 的真因数为
1, 2, 3, 6, 9, 18, 27, 37, 54, 74, 111, 222, 333, 666，
其和为 1 + 2 + 3 + 6 + 9 + 18 + 27 + 37 + 54 + 74 + 111 + 222 + 333 + 666 = 1998。
由于真因数之和不等于 1998，故 1998 不是完全数。

步骤 2：检查 1998 的末位数字为 8，不等于 4，故第二条规则不适用。

步骤 3：将 1998 分解质因数：1998 = 2 × 3^3 × 37，再用可乘性展开。
```

> 这条链选得很讲究：**它的等式是错的，但紧接着的结论是对的。** 真因数之和其实是
> **1563**，不是 1998；而「1563 ≠ 1998，所以不是完全数」这个结论恰好成立。
> 人读到这里会顺着正确的结论滑过去，SymPy 不会。这正是本项目要演示的东西。

## 二、分镜

### 第一幕　0:00–0:20　问题：答对了，不代表答得对

**【画面】** `docs/report.md` §1 的 E9 占比表，全屏。

**【操作】** 念到「1.75%」时鼠标划过 T1 那一行，念到「25.9%」时划过 T4 那一行。不要点击。

**【口播】**（92 字）

> 大模型做数学题，答对越来越容易，但「答得对不对得住」很少有人查。
>
> ProcessBench 全量三千四百条实测：答案对、过程却站不住的比例，从小学题的百分之一点七五，升到竞赛题的百分之二十五点九。题目越难，只看答案越会高估模型能力。

## 三、录制纪律

1. **不要跳过失败。** 如果演示时评估器判错了，就把它留在片子里并说明 —— 这比重录十遍
   取一条完美的更有说服力。同理，P6 是个 null 结果，照说不误：一个说「我测了、没测出来、
   原因是这三条」的项目，比一个只报好数字的项目更可信。

2. **每个数字都要指向文件。** 说到零点八五七，就让 `metrics_corrected.json` 或
   `audit_summary.md` 出现在画面里。片子里出现的每个数字都能在 `results/runs/` 下查到，
   这件事本身就是这个项目最想传达的东西。

3. **口播稿是给你念的，不是给你背的。** 照着念就行，念错一两个字不用重来。真正需要重来的
   只有一种情况：画面上出现的内容和你说的对不上。

4. **不要加旁白解释 UI。** 不用说「现在我点一下这里」。观众看得见，说了反而占时间。

## 四、万一出问题

| 情况 | 处理 |
|---|---|
| MCP 灯不是 🟢 | 停止录制。重启 WorkBuddy，确认 `.workbuddy/mcp.json` 被加载后再来 |
| `/evaluate` 没调工具，模型自己心算了 | 这一条必须重来 —— 第三幕的全部意义就是展示工具调用 |
| 工具调用超时 | 不要干等。停止录制，重跑一次预热，确认稳定后再录 |
| 评估器把第一步判成成立 | **保留，并如实说明**。按纪律第 1 条处理，顺势引到第四幕的检出率零点八五七 |
| 念错数字 | 从当前这一幕的开头重录，不要从头重录 |
