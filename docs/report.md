## 1. 方法

对每条样本执行 `/evaluate` 完整流程：
1. `check_step_symbolic(steps)` 做确定性等式校验 → 取 `first_false_step` 与 `needs_llm_review`；
2. 对工具标 `needs_llm_review` 的步骤做语义审查（E2 概念误用 / E5 跳步 / E7 幻觉引用），默认成立、举证判错、宁可漏报不可误报；
3. 全局复核（E1 题意误读 / E4 条件遗漏 / E6 循环论证 / E9 答案对但过程不成立）；
4. `verdict_record` 落盘（`process_valid` / `first_error_step` / `error_type` / `evidence` / `layer`）。

经验：`check_step_symbolic` 对自然语言步骤几乎全返 `UNKNOWN`（仅能抓到显式算术等式，如
omnimath-7 第1步约数求和 1563≠1998 被判 `FALSE`）。**真正的区分力来自 L3 语义层**，这也印证了
项目设定中 L2/L3 必须补足 L1 触发率的设计意图。

## 5. 稳定性说明（诚实声明）

`stability.step_mode_ratio = 1.0` 达到门槛，但**此数值来自 5 次「相同 verdict 的重复落盘」**，
并非 5 次独立重新评判。本运行未做 5×独立重评（成本过高），因此该指标验证的是
「记录一致性与评估器确定性」，而非「评估器跨次方差」。建议后续以独立重评（不同 seed / 不同会话）
补做真实方差估计。

## 7. 失败模式归因

1. **T4 漏检 1 例**：高难度证明题中，评估器对某条「看似正确」的解答未找到具体错步（可能错在
   更隐蔽的建模或结论非最优）。对应 detection 在 T4 降至 0.667。
2. **精确定位退化**：T3/T4 的精确步号命中仅 0.33，错步常偏 1 步（如 olympiadbench 类长代数链，
   首错步落在 6–8 附近，评估器在 7 或相邻步摆动）。`±1` 容忍下仍 0.83，实用可接受。
3. **E9 召回 0.75**：4 个 E9 中抓到 3 个；漏掉的 1 个属于「过程含无害错步但答案对」的边界情形，
   评估器倾向「默认成立」，与「宁可漏报」原则一致——代价是 E9 召回略低于 1。
